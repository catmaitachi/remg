# T21 · Religar + polimento final do front: plano

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fazer o modo Religar (achar rota → chaves piscam → análise com elas fechadas), com um painel honesto sobre o religamento parcial, o painel Selecionado do Observar, a flag `criticos` guardada e uma passada do impeccable.

**Architecture:** o estado do religamento entra no reducer de `tela/falhas.ts`, com a mesma `versao`. Uma função pura, `pedidoPendente`, diz qual pedido o App faz a cada versão (rota ou análise), e assim só existe um efeito no App. O mapa ganha a camada `rota`. A barra ganha os componentes `Religamento` e `Selecionado`.

**Tech Stack:** React 19 + TypeScript, deck.gl 9 (`PathLayer`, `ScatterplotLayer`), vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-t21-religar-design.md`

## Global Constraints

- O contrato 06 e os mocks **não mudam**. O pedido do `/rota-alternativa` é igual ao do `/analise`.
- Os textos da tela ficam em português. A potência sai sempre pelo `formatarPotencia` (kVA abaixo de 1000, MVA acima).
- Proibido mostrar "Toda a cidade com luz" ou 100% quando o religamento vigente for parcial.
- No mock (`VITE_USAR_MOCK=true`) o Religar fica desligado, com o texto "precisa do servidor".
- Com o sistema pedindo movimento reduzido ou a animação desligada, o anel da chave não pisca.
- Nenhuma dependência nova. Ninguém escreve no README: a subseção "Na tela" fica para o Lucas.
- Testes: `npm --prefix front test`. Tipos e build: `npm --prefix front run build`. Lint: `npm --prefix front run lint`.

## Review Focus

1. Mudar a lista de falhas no meio dos ~8 s da rota: a rota velha não pode fechar chaves na lista nova. Teste na Task 1 ("rota velha é ignorada").
2. Achar rota uma segunda vez, depois de um religamento parcial: o pedido leva as chaves já fechadas, e as novas se somam sem repetir. Teste na Task 1.
3. O servidor responde `chavesParaFechar` vazio: nada pisca, o painel diz "Nenhuma chave alcança a área sem luz" e não fica preso em "calculando". Teste na Task 1.
4. A rota dá erro (400 ou 500, ou o servidor caiu): o aviso diz "Não deu para achar a rota", e a lista e a última análise boa continuam. Teste na Task 1.
5. Clique no Observar numa chave fechada, numa linha AT ou num trecho sem fluxo: o Selecionado mostra o tipo certo e "sem fluxo", sem quebrar. Teste na Task 3.

### Task 1: Estado do religamento no reducer

**Files:**
- Modify: `front/src/tela/falhas.ts`
- Test: `front/src/tela/falhas.test.ts`

**Interfaces:**
- Produces:
  - `pedidoDe(falhas: Alvo[], chavesFechadas?: string[]): Pedido`. O padrão de `chavesFechadas` é `[]`, e o teste que já existe continua valendo.
  - `type FaseRota = "buscando" | "religando" | "pronta" | "erro"`.
  - `interface EstadoRota { fase: FaseRota; resultado: RotaAlternativa | null; semLuzAntes: number /* kVA */; chavesAntes: string[] }`.
  - `EstadoFalhas` ganha `chavesFechadas: string[]`, `rota: EstadoRota | null` e `faltando: number` (kVA que o religamento vigente não devolveu), vazios ou 0 em `ESTADO_INICIAL`.
  - Ações novas em `Acao`:
    - `{ tipo: "acharRota" }`;
    - `{ tipo: "rota"; versao: number; resultado: { ok: RotaAlternativa } | { erro: string } }`.
  - `pedidoPendente(e: EstadoFalhas): { tipo: "rota" | "analise"; pedido: Pedido } | null`.
  - (Codex) Não há função `faltandoNoReligamento`: o faltante é o campo `faltando`, que sobrevive a uma segunda busca e só zera quando a lista muda.

**Regras:**
- `acharRota`:
  - sem falhas, ou com `calculando`, não faz nada;
  - senão, `versao + 1`, `calculando: true`, `erro: null` e `rota = { fase: "buscando", resultado: null, semLuzAntes: (atual?.semEnergia.demanda ?? 0) + faltando, chavesAntes: chavesFechadas }`. O `faltando` **não** muda aqui (Codex 1).
- `rota` com a versão errada é ignorada. Com a versão certa:
  - `ok` com chaves: `chavesFechadas` = as atuais mais as novas, sem repetir; `rota.fase = "religando"`; `versao + 1`; `calculando` continua `true`;
  - `ok` sem chaves: `fase: "pronta"`, `calculando: false` e `faltando` sem mudar;
  - `erro`: `fase: "erro"`, `erro: <msg>` e `calculando: false`.
- `resposta` (análise) aceita com `rota.fase === "religando"` (Codex 2):
  - `ok` → `fase: "pronta"`, e `faltando = resultado.parcial ? max(0, semLuzAntes − resultado.religado.demanda) : 0`;
  - `erro` → `fase: "erro"`, `chavesFechadas = chavesAntes` (as chaves novas não valem sem a análise) e o `atual` fica a análise anterior.
- `alternar` e `restaurarTudo` (via `comLista`) zeram `rota`, `chavesFechadas` e `faltando`.
- `pedidoPendente`:
  - sem `calculando`, devolve `null`;
  - com `rota?.fase === "buscando"`, devolve `rota`;
  - senão, com falhas, devolve `analise`.
  - O pedido é sempre `pedidoDe(falhas, chavesFechadas)`.

- [ ] **Step 1: Escrever os testes que falham**, em `falhas.test.ts`, usando o mock `../mocks/rota-alternativa.json` (`chavesParaFechar: ["c:1"]`, `parcial: false`):
  - `"pedido leva as chaves fechadas"`: `pedidoDe([t1], ["c:1"])` → `{ falhas: { arestas: ["t:1"], subestacoes: [] }, chavesFechadas: ["c:1"] }`;
  - `"religar: rota → análise com as chaves → pronta"`:
    - depois de `passos(pronto, t1)` + resposta ok, `acharRota` dá `pedidoPendente` = `{ tipo: "rota", pedido.chavesFechadas: [] }`;
    - a rota ok → `chavesFechadas: ["c:1"]`, `rota.fase: "religando"`, e `pedidoPendente` = `{ tipo: "analise", pedido.chavesFechadas: ["c:1"] }`;
    - a resposta da análise → `rota.fase: "pronta"`, `calculando: false`, `pedidoPendente` null;
  - `"rota velha é ignorada"`: `acharRota`, depois `alternar t2`, depois a rota com a versão antiga → `chavesFechadas: []`, `rota: null`;
  - `"segunda rota soma as chaves sem repetir"`: com `chavesFechadas: ["c:1"]` e a rota respondendo `["c:1", "c:2"]` → `["c:1", "c:2"]`;
  - `"rota sem chaves fica pronta sem calcular"`;
  - `"erro na rota mantém lista e análise"`: `fase: "erro"`, `erro` preenchido, `atual` intacta;
  - `"mudar a lista zera o religamento"`;
  - `"faltando só com parcial pronto"`: `semLuzAntes` 10040 e `religado.demanda` 2.739 com `parcial: true` → `faltando` 10037,261; com `parcial: false` → 0;
